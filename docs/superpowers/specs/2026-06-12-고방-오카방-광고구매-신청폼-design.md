# 고방 오픈카톡방 광고 구매 신청폼 — 설계안

> 확정일 2026-06-12. 빌리투어 신청폼(`billytour_request`) 패턴 복제. 대기 중인 광고주 1명 즉시 처리 + 6/25~ for_Release **고방 광고 어드민**의 구매자 페이지 피처로 흡수 가능하도록 설계.

## 결론 (한 줄)
고방 오픈카톡방("청년 주거·주택·자금 지원 정보공유", 1,178명)의 **스폰서 게시 광고**를 광고주가 직접 신청하는 폼. 제출 → 검수 → 검수통과 시 토스 결제링크 카카오 알림톡 자동발송 → 결제 → 게시(수동).

## 상품
| 상품 | 정책 | 결제액(VAT 포함) |
|------|------|------------------|
| 게시 1회 | [광고] 표기 업로드, 올린 날 다음날 자정까지 유지 | **55,000** |
| 게시 1회 + 공지 고정 24h | 위 + 공지 고정 24시간 | **110,000** |

- 토스는 카드결제이므로 **VAT 포함 최종 결제액**으로 등록. 세금계산서 원하는 사업자만 별도 발행.
- 문구/이미지는 **사전 검수 후** 게시. [광고] 표기 필수.

## 아키텍처 (빌리투어 패턴 복제, 단순화)
```
[광고주] 신청폼(GitHub Pages 정적 HTML/Vanilla JS)
   │  submitForm (광고문구·이미지1장·상품·연락처·게시희망일·사업자정보)
   ▼
[GAS] doPost → 구글시트 `신청 내역` 저장 + 이미지 Drive 저장
   │
[운영자] 시트에서 검수(방 규칙 위반 확인) → 결제링크발송 드롭박스 '발송하기'
   ▼
[GAS onEdit] SOLAPI 카카오 알림톡 발송 (상품에 맞는 토스 결제링크 #{결제링크} 치환)
   ▼
[광고주] 결제 → 운영자 결제완료일 기입 → 게시일에 [광고] 표기로 등록(수동)
```

**빌리투어 대비 제거**: 지점 자동검증(`resolvePlace`)·유튜브 크롤링(`ytInfo`/gas-crawler)·작업내역(제작관리) 탭. 광고는 제작물이 없으므로 불필요.
**빌리투어 대비 추가**: 광고 이미지 1장 **파일 업로드 → GAS가 Drive 저장 후 URL 시트 기록**(빌리투어는 URL 입력만 있었음).

## 컴포넌트
### 1. 신청폼 (`index.html`) — 순수 HTML + Vanilla JS
상단 상품 안내 섹션 + 폼 통합(별도 React 랜딩 없음). 입력 항목:

| 항목 | 타입 | 필수 | 비고 |
|------|------|------|------|
| 상호/광고주명 | text | ✓ | |
| 연락처(휴대폰) | tel | ✓ | 알림톡 발송용 |
| 상품 선택 | radio | ✓ | 게시1회 / 게시+공지고정24h |
| 광고 문구 | textarea | ✓ | 검수 대상 |
| 광고 이미지 | file (1장) | ✓ | jpg/png, base64로 GAS 전송 → Drive 저장 |
| 게시 희망일 | date | ✓ | 정책: 올린 날 다음날 자정까지 유지 |
| 사업자 정보 | text | – | 세금계산서용(상호·사업자번호·이메일), 선택 |
| 방 규칙 동의 | checkbox | ✓ | 집광고·어플·유튜브·블로그·카페 링크 금지 등 사전고지 |

- 디자인: 고방 브랜드 톤. (빌리투어는 U 시그니처 블루였음 → 고방용 팔레트는 구현 단계에서 `colors_and_type.css`로 확정)
- 제출 시 "검수 중" 안내 화면 전환.

### 2. 백엔드 (`gas-code/Code.gs`) — Google Apps Script + 구글시트
시트 2탭(빌리투어 3탭에서 작업내역 제거):
- **`설정`**: 상품·단가·검수기준·활성여부 → **데이터로 분리**(미래 어드민이 카탈로그로 읽음)
- **`신청 내역`**: 아래 컬럼

| 열 | 내용 | 입력 |
|----|------|------|
| A | 신청일시 | 자동 |
| B | 상호/광고주명 | 자동 |
| C | 연락처 | 자동 |
| D | 상품 선택 | 자동 |
| E | 광고 문구 | 자동 |
| F | 광고 이미지 URL (Drive) | 자동 |
| G | 게시 희망일 | 자동 |
| H | 사업자 정보 | 자동 |
| I | 검수 메모 | 수동 |
| J | 결제링크 발송 — `발송대기`/`발송하기`/`발송완료` | 드롭박스 |
| K | 발송시간 | 자동 |
| L | 결제완료일 | 수동 |
| M | 게시 완료 — `대기`/`완료` | 드롭박스 |

**J열 발송 로직 (빌리투어 L열 규칙 복제):**
- 신청 접수 → `발송대기`
- `발송하기` 선택 → 상품에 맞는 토스 결제링크로 알림톡 발송 후 `발송완료`
- 발송완료 후 재선택해도 재발송 안 됨

**GAS action**: `checkAccess`(활성여부), `submitForm`(저장+이미지 Drive 업로드). 유지보수 함수 `setupSheets()`/`setupDropdowns()`/`setupTrigger()`.

### 3. 토스 결제링크 + 노션 허브
- 토스 결제링크 **2종 생성**(게시 55,000 / 게시+고정 110,000) → GAS 상수 `PAY_LINK_BASIC`/`PAY_LINK_PIN` + `index.html` 동기화.
- 노션 "고방 광고상품" 페이지(`6703826995438395956001d30bc52f09`)를 **허브 페이지로 구성**(레퍼런스: "네이버 블로그 상품화-2차" `37b38269954380dcbbd8ff5de1d72e14`). 구조:
  - **관련 URL 콜아웃**(gray_bg): DB(구글시트) · R(신청폼 GitHub Pages) · 결제링크(토스 2종) · 솔라피 콘솔 · 상담/CRM(있으면) · 가설(mention-page)
  - **액션플랜 토글**(한 일 / 남은 일 체크리스트, 날짜 기준)
  - **하위 페이지**: `토스 결제링크 상품 내용`(빌리투어 `💳` 포맷 — 상품명·금액·소개글·교환환불·알림톡문구·노출ON) + 필요 시 업무개요·채널톡 팝업 등
- 노션 허브 = 이 광고상품의 **단일 진실 소스**(관련 URL·진행상황·결제링크 내용 전부 한 페이지).

## 에러 처리
- 이미지 용량 초과(예: 5MB↑)·미허용 확장자 → 폼 단에서 차단.
- GAS 저장 실패 → 폼에 재시도 안내, 운영자 카톡 폴백 문구.
- 알림톡 발송 실패(SOLAPI) → J열 `발송대기` 복귀 + 운영자 확인.

## 테스트
- GAS `submitForm` 단위 테스트(시트 mock).
- 폼 제출 → 시트 1행 + Drive 이미지 1개 E2E(실 GAS, 명시적 실행).
- 알림톡 발송 로직: 상품→링크 매칭 단위 테스트.

## YAGNI (지금 안 만드는 것)
- React 랜딩페이지 (신청폼 1장 통합)
- 작업내역/제작관리 탭 (광고는 제작물 없음)
- 결제완료·게시 상태의 광고주 조회 화면 (운영자 시트로 충분, 어드민 단계에서)
- 다중 오픈카톡방·다중 상품군 (현재 1방·2상품)
